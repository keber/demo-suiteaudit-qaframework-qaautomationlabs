D3 Determinism
Synchronization is sound: D3.fixed-waits is 0, D3.conditional-waits only 2, web-first assertions and expect.poll are used (category-listing.spec.ts:191), and each test seeds its own localStorage, so there is no order dependence in e2e. The weakness is the retry policy: D3.retries-config sets retries to 2 in CI with no explanation in playwright.config.ts, and the CI job only fails on steps.tests.outcome == failure, so a test that passes on retry is reported flaky and stays green with nothing in the repository counting it; the only flakiness figure is a one-off stabilization report of 3 runs. The suite also runs against a public third-party demo site whose data it pins, and cart-management.spec.ts:152 reads the DOM right after a Tab press on the assumption that rendering is synchronous. Retries that absorb flakes without a tracked rate is level 1; measured and controlled flakiness (level 2) is not evidenced.
